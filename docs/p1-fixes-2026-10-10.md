# BlockNotes v0.1.0｜P1 可靠性修复与 Windows 回归

日期：2026-10-10。依据用户提供的独立验收报告，仅处理 BN-P1-01、02、03。书房布局、模型、纹理、GUI 样式和编辑器内核未重做，未增加产品功能。测试与故障注入均使用独立临时数据目录。

## 修复结果

| 问题 | 已复现原因 | 修复 |
| --- | --- | --- |
| BN-P1-01 重复恢复冲突备份增加副本 | 旧 restore 每次遇到原 ID 冲突都生成随机新 ID，未识别既有恢复快照；冲突书架也重复增加 | 附加恢复来源表，以来源 ID + 内容/标签/归属/状态的 SHA-256 指纹跟踪副本；重复导入复用内容仍等价的副本。兼容旧版已存在的恢复副本；被用户修改的副本保留，必要时另建完整旧快照。不同来源 ID、同标题不同内容不会按标题合并 |
| BN-P1-02 自产超过 64 MB 的备份无法恢复 | 桌面读取与浏览器选择文件处硬拒绝超过 64,000,000 bytes；整体 JSON 在界面线程解析 | 桌面文件导出/恢复放在 Worker 中。复用 stream-json Parser/Assembler，逐条解析，暂存在独立临时 SQLite，完整文件解析后才以一个事务合并用户库；浏览器上传原文件至同一后台处理入口。保留旧 schemaVersion 1 JSON 格式 |
| BN-P1-03 Esc 关闭期间弹窗再次出现 | 稳定复现：归档/location 等异步操作未结束时 Esc 先关闭编辑器，迟到操作随后打开箱子。并发动作与 busy 布尔值不能可靠协调结束顺序 | 串行执行领域操作；Esc 等待已开始的动作结束，再 flush 所有修改、最终关闭。待完成关闭合并，按键自动重复忽略。保存失败时保持编辑器、保留草稿并显示错误 |

标题边界一并修复：新恢复副本在 500 字标题范围内保留“（恢复副本）”标记；旧版曾生成的 506 字恢复副本标题可以导入，并可在不改名时继续保存正文。不会静默改写旧标题。

## 数据保护与容量边界

- 数据库由 v1 加法迁移到 v2，仅增加 restore_notes / restore_shelves 来源表和索引。原 notes / shelves 内容结构不变。
- 迁移前生成完整 SQLite 快照：数据目录 `backups/blocknotes-before-v2-*.sqlite`。快照失败则停止升级；迁移有事务。旧程序不支持 v2 数据库，回退时应将升级前快照用于独立目录核对，不直接让旧程序读升级后的库。
- JSON 备份继续使用 format=blocknotes-backup、schemaVersion=1；恢复为合并，不覆盖原 ID 的不同内容，不清空数据。
- 原来已产生的多余副本不会自动删除。修复阻止后续相同快照继续膨胀；用户修改过的副本保留。
- 文件不再受固定 64 MB 总量限制。沿用原有备份结构上限：100,000 篇笔记、1,000 个书架；正文 JSON 长度不超过 8,000,000 字符、正文节点不超过 100,000、正文层级不超过 32。导出检查同一约束，超界时不生成不可恢复文件、不覆盖已存在的备份。
- 本机实测是 16 篇、每篇 750,000 中文字符、约 72 MB 的有效备份。不是无限容量或所有规模性能保证。流式解析内存按条目工作；暂存与目标数据库仍需要足够磁盘空间。
- 完整文件先解析/暂存，再事务合并；截断、重复 ID、非法元数据及 SQL 写入失败均不留下半次恢复或来源记录。临时目录正常完成或报错后清理，原备份文件不会删除。

Windows 大文件测试：真实原生文件对话框由测试选择路径，实际备份写出与恢复走桌面 IPC；验证 16 篇 doc 的 SHA-256、重复恢复新增 0 篇，记录主进程 20 ms 心跳、最大间隔与耗时。数据见 `p1-large-backup-metrics.json`。

最终文件为 72,005,891 bytes；恢复加重复恢复和截图合计约 5.714 秒，采样最大主进程心跳间隔 524 ms。该数值是本机单次测试数据，不是帧率或所有设备性能承诺。

关闭循环包含长正文、即时改名、自动保存、移动书架、归档等待、连续按键；注入 save/location 250 ms 延迟扩大竞态窗口，记录操作开始/结束和关闭时间。循环后重启读数据库核对全部正文与标题。另注入拒绝 UPDATE 的真实 SQLite 触发器，确认 Esc 不关闭失败草稿；移除故障后再次关闭、重开内容一致。数据见 `p1-close-loop-metrics-*.json` 和 Playwright JSON 附件。

开发过程中一次打包生成的 app.asar 出现文件偏移错位，导致只显示 Electron 默认页面，九项测试均未进入产品流程；该轮不计为通过，保留 `windows-initial-invalid-package.*` 与 `invalid-package-diagnostic.log`。停止在打包期间修改输入文件后重建，并增加包内代码哈希校验，才运行最终实机测试。该问题与产品的 Esc / 备份断言分开记录。

## 未解决 / 未验证清单

1. 原验收包里那次 Esc 截图超时没有完整操作时序，无法证明它与本轮稳定复现的“迟到归档重新开窗”是同一原因。本轮已修复可复现竞态，并用关闭循环和原完整视觉脚本回归；不宣称解释了所有历史偶发事件。
2. 大于本轮约 72 MB 库规模的峰值内存、低磁盘空间下用户体验、超大库刷新和长时间性能未跨设备测量。当前库快照仍一次向界面提供全部笔记，超大库的界面内存优化不在本轮扩展。
3. Windows 真实中文 IME 候选窗、组合态撤销、多屏 DPI、不同 GPU 和声卡输出人工验收未补做。已保留既有中文 DOM、音频解码与实际播放测试。
4. P2 容器布局、书架物理隐喻、原版逐像素视觉基准、连续运行跨日自动备份等未处理；本轮不改这些设计。
5. 旧重复副本保留，未进行自动清理；没有签名安装器或新增公开发行方案。

## 启动和复现

先从旧版 Esc 菜单保存并退出，再双击 `release/p1-fix/win-unpacked/BlockNotes.exe`，保持完整目录。不搬移或清空用户笔记目录。

```powershell
npm run check
npm test
npm run build
& '.\node_modules\.bin\electron-builder.cmd' --config electron-builder.local.cjs --config.directories.output=release/p1-fix --win dir
node scripts/verify-package.mjs release/p1-fix/win-unpacked
$env:BLOCKNOTES_TEST_EXE = (Resolve-Path 'release/p1-fix/win-unpacked/BlockNotes.exe').Path
npm run test:e2e
npm run test:e2e -- --grep BN-P1-03 --repeat-each=3
node scripts/visual-smoke.mjs
```
