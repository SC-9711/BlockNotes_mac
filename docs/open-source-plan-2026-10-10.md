# BlockNotes 开源准备与发布计划

日期：2026-10-10。用户已确认：GitHub 账号 `tonniescj-hub`，计划仓库名 `BlockNotes`，项目自身代码采用 MIT。本轮范围是本地准备，不创建远程仓库、不推送、不发布 Release。

## 发布形态

完整公开项目自身源码、构建脚本、测试、架构文档、原创建模实现、原创图标和虚构演示文案。保留依赖锁文件与第三方版权声明。仓库名使用 BlockNotes，不将 Minecraft 作为主品牌。

原版纹理、模型 JSON、GUI、字体、OGG 和唱片仍只保留在忽略的本地资源包。公开源码可复现功能，但需要用户在自己的机器上准备可使用的资源；源代码许可不会授权游戏素材。依据：[Minecraft EULA](https://www.minecraft.net/en-us/eula)、[Usage Guidelines](https://www.minecraft.net/en-us/usage-guidelines)。这是当前发布边界，不是对该独立应用获得官方授权的认定。

建议分两步发布：先让开发者获得可构建的完整源码；完成本地资源导入与首次启动验收后，再提供普通用户下载的 Windows 程序。不要把现在的私人 `pack:local` 直接上传到 Release。

## 已完成的准备

- 根目录 MIT 许可证；生产包保留 LICENSE 和 THIRD_PARTY_NOTICES。
- 面向陌生使用者的 README，说明资源前提、开发步骤、功能、数据位置与构建限制。
- CONTRIBUTING、SECURITY、Bug 模板和 PR 模板。
- Windows GitHub Actions 工作流：只读权限、锁定 action commit、源码检查、类型检查、单元测试及构建；不下载游戏素材，不自动发布。
- `.gitignore` 增补环境变量、数据库、证书私钥及备份目录；既有数据目录、资源包、视频、截图和交付件仍忽略。
- `npm run audit:source`：检查待提交文件与所有可达 Git 历史中的资源路径、大文件、常见令牌/私钥模式和个人路径。属于模式审查，不代替完整秘密扫描或逐项素材授权核查。
- `verify-package --public`：除了 ASAR 内资源排除，还检查解包程序外围目录，防止 `extraResources` 意外包含资源或数据库。

## 下一轮发布前的必要工作

### 1. 普通用户的资源准备

优先实现从用户本机已安装的 Java 1.21 客户端与 asset index/objects 导入所需资源。用户可以选择自己的合法资源目录；不替用户提供共享素材下载包，不把“拥有游戏”描述为取得本应用独立再分发授权。

资源生成写入用户可写的专用目录，校验版本、哈希、必需模型/纹理、字体与音频。成功后再切换生效，失败保留旧可用资源。导入过程与 SQLite 独立，不清理、覆盖笔记。

当前程序只在开发 `dist/minecraft` 或打包 `resources/minecraft` 查找文件；要支持普通用户导入，需要补充用户资源目录查找和首次启动说明。这是发布所需的小范围工程工作，本轮尚未实施。不要要求用户向受保护的安装目录手工复制文件。

### 2. 干净机器验收

在没有开发缓存、没有既有笔记的 Windows x64 环境执行：下载安装程序 → 明确提示资源缺失 → 用户本地导入 → 新建/中文编辑/保存 → 讲台阅读 → 书架迁移/删除 → 归档/回收/搜索 → 备份恢复 → 重启读取。

另做有旧数据库和旧备份的升级回归，覆盖 P1 冲突去重、大文件恢复和 Esc 异步关闭。测试数据全部为虚构夹具，程序不联网存储笔记。

### 3. 发布内容

- 根目录 README 提供经过实际验证的下载和资源初始化步骤，替换“准备版本”状态。
- 用虚构笔记制作 3D 书房、书与笔、讲台、书架等截图；逐张检查个人数据，并单独核查截图使用规则。不公开历史个人截图或微信视频。
- 制作 Windows x64 程序 ZIP、SHA-256 校验文件、版本说明和已知问题清单。公共包检查必须以 `--public` 通过，禁止选择带 Local 字样的资源包。
- 未签名程序如实标注；不要求使用者关闭系统保护。代码签名可另行评估，不阻止源码公开。
- 审核正式 README、许可声明、发行包和仓库所有者联系方式；MIT 仅覆盖项目有权许可的内容。

### 4. GitHub 上线

用户确认发布时，再在 `tonniescj-hub/BlockNotes` 创建 public 仓库，用干净源码初始提交建立 `main`，保留本地开发仓库。添加 Topics、简介、Issues、Discussions（按需要）及私密漏洞报告；CI 实际通过后创建版本 Tag 和 Release。

准备中的 GitHub 仓库地址：`https://github.com/tonniescj-hub/BlockNotes`。本轮不将它当作已存在的下载地址，也不写入 remote。
