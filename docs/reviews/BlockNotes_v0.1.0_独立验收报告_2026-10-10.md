# BlockNotes v0.1.0｜独立项目验收报告

**验收日期：** 2026-10-10  
**验收资料：** `BlockNotes_GPT验收包_2026-10-10.zip`  
**结论：** 有条件通过（内部原型 / MVP 阶段），暂不认定正式发布就绪  
**证据边界：** 审查了源代码、交付说明、截图、测试日志和 manifest；未取得 Windows EXE、本地 Minecraft 原始资源及个人数据，无法在本环境完成 Windows 实机、中文 IME、音频听审、显卡性能和安装器验收。

## 1. 产品与体验结论

- **产品方向基本成立**：固定 3D 书房、有限鼠标视差、场景功能方块、九格快捷栏、书与笔页面均已体现。未添加角色漫游、战斗或其他无关 Minecraft 系统。
- **视觉明显改善**：`screenshots/room.png` 展示了真实 3D 空间、嵌入式书墙、梁柱、窗户、讲台、箱子、桌椅、盆栽、地毯及灯笼。方块纹理、道具图标和 HUD 与 Minecraft Java 版目标较为接近。
- **核心功能具备可信测试证据**：源码包含 SQLite 笔记库、富文本书页编辑器、搜索、分类、归档、恢复、全量备份、Markdown 导出；交付的 Playwright 桌面日志显示 6 组集成测试通过。
- **仍有视觉/交互差异**：书架、搜索及归档容器是为笔记产品定制的大型灰色 GUI，不能视为原版游戏 UI 的逐像素复刻；书架中的书与场景内具体格子尚未形成直观、一一对应的物理存放体验。字体度量、世界光照和翻页也存在实现近似。

## 3. 必须修复的问题（按优先级）

### BN-P1-01｜冲突备份重复导入不断生成恢复副本

**定位：** `source/server/storage.cjs`，`restore()` 中针对 `existing` 的判断及新随机 ID 插入分支。  
**独立复现：**
1. 创建笔记“同一本书”，正文“早期内容”，导出备份。
2. 将原笔记改为“新内容”。
3. 对旧备份执行恢复 3 次。
4. **实际：** 3 次各报告 `added:1`，最终产生 4 本笔记，包括 3 本“同一本书（恢复副本）”。
5. **预期：** 第一次保留冲突副本，重复导入同一备份应检测已恢复的完全相同副本，不继续增加。

**影响：** 重复备份恢复导致笔记膨胀、检索杂乱，备份合并不满足幂等要求。不会直接覆盖原文，但影响数据一致性和可理解性。  
**修复方向：** 在不覆盖用户数据的前提下记录恢复来源 ID / 快照指纹，或在恢复时查找等价来源副本；补充“冲突备份连续导入 3 次”和“合法的同标题不同内容不能错误去重”两类测试。

### BN-P1-02｜自身可以导出的有效大备份无法导入

**定位：** `source/electron/main.cjs` 中 `restoreFile` 的 `fs.statSync(...).size > 64_000_000` 判断；`source/src/App.tsx` 中浏览器回退恢复的同等上限。  
**独立复现：** 构造 16 篇每篇约 75 万中文字符的有效笔记，调用现有 `backup()`，得到 JSON 备份 **72,005,551 bytes**；该数据超过恢复接口 **64,000,000 bytes** 的硬限制。

**影响：** 随着用户笔记积累，备份导出与导入不对称。极端情况下只有备份而无法通过应用恢复。  
**修复方向：** 优先明确产品支持的笔记库容量和单份备份容量；允许已导出的有效备份恢复，或提供兼容的压缩/分批/流式恢复方案；避免简单取消上限后让巨大 JSON 导致界面卡死。增加大容量导出—恢复端到端测试。

### BN-P1-03｜关闭弹窗存在一次自动化超时，尚待定位

**定位：** `evidence/visual-first-attempt.log`、`source/scripts/visual-smoke.mjs` 的 `close()` 步骤、`source/src/App.tsx` 的 Esc/close/openPanel/flush 链路。  
**实际：** 一次视觉回归测试在 Esc 关闭后等待 dialog 消失超时，重跑成功。  
**性质：** *待调查风险，尚未独立复现为稳定产品缺陷*。  
**处理：** 在编辑大字数、自动保存刚触发、改名/移动书架和连续按 Esc 情况下做循环测试，附状态与时间记录，查清是测试时序还是用户可见交互卡顿。

## 4. 优化项与非阻塞问题

- **BN-P2-01｜大型容器 GUI 信息密度不理想：** `screenshots/shelf.png`、`chest.png`、`search-copy-fixed.png` 中有明显空白；建议在不破坏原版灰色容器视觉的前提下按内容量优化槽位数量、位置、标题层级和鼠标悬停信息。
- **BN-P2-02｜书架的物理隐喻尚可增强：** 当前功能上可通过元数据选择书架，3D 区域与分类相连；后续可以增加书籍放入、抽取的视觉反馈，或者书架存量变化，不必开发实体玩家与完整背包系统。
- **BN-P2-03｜1:1 视觉还原尚未定量证明：** 缺少统一原版 1.21 实机截图与自家截图的同分辨率、同 UI scale 对照。字体度量和静态近似光照应作为视觉差异记录，不轻易以“完全复刻”对外宣传。
- **BN-P2-04｜自动备份触发语义：** `source/server/storage.cjs` 在应用启动时创建当天快照；若软件连续运行多天，不会每天自动生成一次。这与“每日自动备份”的常规理解不同，应调整实现或文案。
- **BN-P2-05｜真实设备与输入：** Windows 中文拼音 IME 组合输入、候选窗口位置、撤销、长时间运行、100%/125%/150% DPI、不同 GPU、窗口缩放、低配置 WebGL 降级均需实机手动验收。
- **BN-RELEASE-01｜资源授权为独立发布门槛：** 本机原版 Minecraft 模型、纹理、字体和声音不因其可获取而自动获得再分发许可。当前许可说明能体现风险意识；公开发布前必须合法解决素材授权或采用可分发替代资源。本验收不等同于版权许可确认。

## 5. 建议下一轮开发安排

**阶段 A：可靠性（先做）。** 修复 BN-P1-01 与 BN-P1-02，并定位 BN-P1-03；测试真实备份恢复幂等性、冲突副本保护、大文件恢复、异常退出。**不改动既有笔记格式和正常用户数据。**

**阶段 B：少量体验打磨。** 优化书架/箱子容器的空白比例、标签与光标反馈；让存书/取书更具游戏感；不再大幅重构 3D 场景，不引入玩家运动或世界生成。

**阶段 C：独立 Windows 实机回归。** 真实 IME、屏幕缩放、性能、窗口关闭、备份恢复、唱片/音效；提供最新版完整可运行目录或签名/安装包供独立验收。

## 6. 可直接发给 Codex 的修复任务

> 请阅读 `BlockNotes_v0.1.0_独立验收报告_2026-10-10.md`。本轮属于验收后可靠性修复，不做新功能扩张，不推翻当前 3D 场景和视觉成果。优先解决：① 同一份冲突备份重复恢复会无限创建“恢复副本”；② 已成功导出的超过 64 MB 的有效备份无法被恢复；③ 一次 Esc 关闭弹窗的视觉脚本超时需定位根因。分别建立先失败后通过的回归测试，确保数据绝不静默覆盖、删除或损坏。必要时改进恢复格式或执行方式，但必须兼容已有备份；在独立临时目录进行所有破坏性测试。完成后运行 TypeScript 检查、单元测试、Windows 版 E2E、真实备份恢复及窗口关闭循环测试，交付修复差异、日志、未验证风险和新版实机截图。通过以上可靠性门槛后再考虑容器界面与书架存放体验的细节优化。

**专业判断：** v0.1.0 已达到“可以继续内部使用和打磨”的阶段；正式公开发布之前，应优先关闭可重现的数据备份问题与实机验证缺口。
